## Description

Algorant requested a Task for remediation and verification before dotfiles becomes public. The chosen direction is ONE public dotfiles repository, with mise synchronizing safe configuration and credentials kept outside Git. Do not introduce a separately maintained public mirror/private dotfiles pair. This Task is a publication-safety prerequisite for task-1 in the Algorant portfolio workspace; it does not own the README rewrite or permission to change GitHub visibility.

Baseline evidence: docs/dotfiles-verification.md. A temporary mirror at master 53c1c9c contained 1,507 reachable commits. Current tracked snapshots had zero Gitleaks findings, but history contained OpenAI and Anthropic API-key assignments (including a duplicate Anthropic key in a backup), an Exa key in old Pi configuration, and an expired OpenAI OAuth JWT in an old agent session. Historical Zsh history and agent-session data also require privacy review. One Gitleaks finding was a Worker handoff identifier, not a provider key. No credential values are recorded in these notes, and active/revoked API-key status remains unknown. Refresh this baseline before remediation.

Plan the work in phases before any live mutation: confirm credential revocation/rotation; inventory all Git refs, ordinary checkouts and separate mise history stores; agree on the exact history-cleaning scope; verify the actual mise automatic-publishing path and a prevention mechanism in disposable state; agree on and implement vault-backed secrets handling; coordinate cleanup across desktop (Arch WSL), laptop (Niri/Noctalia), and homelab (headless Arch); then perform fresh-clone scans and authorized end-to-end synchronization checks. Pause all publishing writers under an approved plan before replacing history, and do not allow old ancestry to return from another clone or watcher. Do not assume an ordinary checkout pull cleans mise's separate history store.

fnox backed by Proton Pass is the intended secrets-management direction to evaluate and finalize in the implementation plan. fnox is already installed for evaluation; current Ketch credentials use SecretSpec/Proton Pass and an excluded local Ketch config. Store references, not values, in Git. Account for headless authentication, least-privilege command-level injection, and applications that persist credentials locally. Do not retain superseded plaintext secret-loading or parallel resolver paths once their replacement is verified. Exclusion/encryption/fnox adoption does not erase historical plaintext.

Verification gaps to resolve: the desktop was not reachable by its SSH name; laptop and homelab systemd history services were active but mise reported declared-not-running. Matching shared files were observed, not an end-to-end propagation test.

This is a coordination and planning contract, not an unattended cross-repository Worker assignment. Implementation belongs in dotfiles' own existing Tandem workspace under its instructions; derive bounded executable work and repository-native validations after the plan and publishing mechanism are verified. Task creation is not authorization for live changes, credential operations, pushes, or history replacement.
